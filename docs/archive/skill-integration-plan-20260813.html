在每个 Skill 的 scripts/ 下放 bidboard_client.py,统一封装 API 调用。后端 / 前端 / 失败兜底全自动。

# scripts/bidboard_client.py - 通用客户端,所有 Skill 复用
import os, json, urllib.request, urllib.error
from datetime import datetime

BOARD_URL = os.environ.get("BIDBOARD_URL", "http://127.0.0.1:8765")
TOKEN     = os.environ.get("BIDBOARD_TOKEN", "")

def _post(path, payload):
    try:
        req = urllib.request.Request(
            BOARD_URL + path,
            data = json.dumps(payload).encode("utf-8"),
            headers = {"Content-Type": "application/json", "Authorization": f"Bearer {TOKEN}"},
            method = "POST"
        )
        with urllib.request.urlopen(req, timeout=3) as r:
            return {"ok": True, "data": json.loads(r.read())}
    except (urllib.error.URLError, TimeoutError, json.JSONDecodeError) as e:
        # 兜底:写入本地队列,下次启动时重试
        _enqueue_retry(path, payload)
        return {"ok": False, "queued": True, "err": str(e)}

def _enqueue_retry(path, payload):
    qfile = os.path.expanduser("~/.bidboard_queue.jsonl")
    with open(qfile, "a") as f:
        f.write(json.dumps({"path": path, "payload": payload, "ts": datetime.now().isoformat()}) + "\n")

# ===== 公开 API =====
def create(code, client, **kw):
    return _post("/api/bids", {"code": code, "client": client, **kw})

def add_ai_ready(code, item, source_tag=""):
    return _post(f"/api/bids/{code}/ai_ready", {"value": item, "source": source_tag})

def set_stage(code, stage):
    return _post(f"/api/bids/{code}/stage", {"value": stage})

def set_block(code, block_reason):
    return _post(f"/api/bids/{code}/block", {"value": block_reason})

def set_human_todo(code, todo_list):
    return _post(f"/api/bids/{code}/human_todo", {"value": todo_list})

def update_flow_node(code, node_id, status, block_reason=""):
    return _post(f"/api/bids/{code}/flow/{node_id}", {"status": status, "block_reason": block_reason})

## 一、职责
每日 09:45 跑一次,执行三件事:
1. 重算 priority(按 §6.5 算法:T≤3→P0, T≤7→P1, 其他→P2;+ 阻塞升级)
2. 写 last_sync 字段(证明看板是"活的")
3. 检查 P0 客户,如 stage/block 变化 → 触发 p0-watcher(微信告警)

## 二、执行步骤

### 步骤 1:拉取所有 bids
GET /api/bids → 列表

### 步骤 2:逐个重算 priority
for bid in bids:
    old_priority = bid.priority
    new_priority = calc_priority(bid, today="2026-08-10")
    if new_priority != old_priority:
        PATCH /api/bids/<code>/priority {value: new_priority}
        log_event("priority 变化", bid.code, old → new)

### 步骤 3:写 last_sync
for bid in bids:
    PATCH /api/bids/<code>/last_sync {value: now()}

### 步骤 4:触发 P0 看门狗

### 步骤 5:幂等性
同一天多次跑,结果应一致(不重复触发告警)。用 "今日已刷新" 标记。

#!/usr/bin/env python3
import os, json, urllib.request
from datetime import datetime, timedelta

BOARD_URL = os.environ.get("BIDBOARD_URL", "http://127.0.0.1:8765")
TOKEN     = os.environ.get("BIDBOARD_TOKEN", "")
TODAY     = datetime.now()

def fetch_bids():
    req = urllib.request.Request(BOARD_URL + "/api/bids",
        headers={"Authorization": f"Bearer {TOKEN}"})
    with urllib.request.urlopen(req) as r:
        return json.loads(r.read())

def calc_priority(bid):
    if not bid.get("due_at") or bid["due_at"] == "持续":
        return "P2"
    if bid.get("flow", {}).get("nodes", []):
        if all(n["status"] == "done" for n in bid["flow"]["nodes"]):
            return "P2"
    due = datetime.fromisoformat(bid["due_at"].replace(" ", "T"))
    days = (due - TODAY).days
    if days <= 3: priority = "P0"
    elif days <= 7: priority = "P1"
    else: priority = "P2"
    # 阻塞升级
    has_block = any(n["status"] == "blocked" for n in bid.get("flow", {}).get("nodes", []))
    if has_block:
        if priority == "P1": priority = "P0"
        elif priority == "P2": priority = "P1"
    return priority

def patch(code, field, value):
    req = urllib.request.Request(
        BOARD_URL + f"/api/bids/{code}/{field}",
        data = json.dumps({"value": value}).encode(),
        headers = {"Content-Type": "application/json", "Authorization": f"Bearer {TOKEN}"},
        method = "PATCH")
    urllib.request.urlopen(req).read()

def main():
    bids = fetch_bids()
    p0_list = []
    for bid in bids:
        new_p = calc_priority(bid)
        if new_p != bid.get("priority"):
            patch(bid["code"], "priority", new_p)
            print(f"{bid['code']} priority: {bid.get('priority')} → {new_p}")
        patch(bid["code"], "last_sync", TODAY.isoformat())
        if new_p == "P0":
            p0_list.append(bid["code"])
    if p0_list:
        print(f"P0 客户: {p0_list} → 触发 p0-watcher")
        # os.system(f"workbuddy run p0-watcher --clients={','.join(p0_list)}")

if __name__ == "__main__":
    main()

import json, requests, os
from datetime import datetime, time

SSE_URL    = "http://127.0.0.1:8765/api/bids/stream"
LARK_URL    = "https://open.feishu.cn/open-apis/im/v1/messages"

def is_silent():
    h = datetime.now().hour
    return h >= 23 or h < 7

def send_lark(text):
    requests.post(LARK_URL, json={
        "receive_id": "duke_user_id",
        "msg_type": "text",
        "content": json.dumps({"text": text})
    }, headers={"Authorization": "Bearer " + os.environ["LARK_TOKEN"]})

def on_event(event):
    bid = event.get(data, {})
    if bid.get("priority") != "P0": return
    if event["type"] not in ["update.stage", "update.block"]: return
    if is_silent(): return
    send_lark(f"🚨 P0 告警\n客户: {bid['client']} ({bid['code']})\n字段: {event['field']}\n新值: {event['value']}\n时间: {datetime.now()}")

# 启动 SSE 长连接
import sseclient
events = sseclient.SSEClient(SSE_URL)
for event in events:
    try:
        on_event(json.loads(event.data))
    except Exception as e:
        print(f"err: {e}")

10风险与回滚
8 个 Skill 同时改造,任何一步错都可能让看板写脏数据。回滚预案必须先想清楚。
🔴 Skill 改造不向后兼容

改造后 Skill 调用 bidboard_client 但 workbench 没起 → Skill 阻塞。
缓解:wrapper 有本地队列兜底,workbench 不起也不会崩 Skill。

🔴 看板写脏数据

多个 Skill 同时写同一 bid,字段互相覆盖。
缓解:每个字段写之前先 GET 读最新,做字段级合并而非整条覆盖。

🟡 性能开销

8 个 Skill 每个都调 HTTP,工作台可能扛不住。
缓解:批量接口(P2 加):POST /api/bids/batch 一次写多条。

🟡 重放队列堆积

workbench 长期没起,队列堆积 1000+ 条。
缓解:队列文件大小限制 1MB,超出转警告 + Slack。

🔴 敏感字段泄露

报价 / 合同金额写入 webhook。
缓解:wrapper 增加 __redact__ 黑名单字段,写 webhook 前脱敏。

🔵 跨平台时间差

Skill 跑完到看板显示延迟 500ms+。
缓解:本地优先:Skill 先写 localStorage(同浏览器内秒同步),再异步同步到后端。

回滚预案

  1. 每个 Skill 改造时:原 SKILL.md 备份到 ~/.workbuddy/skills/_archive/<skill>_<date>.md
  2. 每个 Skill 跑通 3 天,确认数据 OK,再继续下一个
  3. 任何 P0 看板数据问题 → workbuddy run bidboard-restore --from=~/.bidboard_backup_<date>.json
  4. 改造期间,看板的"客户卡"全部标 priority_manual=true,避免自动算覆盖
