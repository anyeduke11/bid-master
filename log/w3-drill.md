## 二、如实记录：返工与发现

1. **审计修复 vs 机检字数冲突（本演练最有价值的发现）**：修复第 3/4 项（佐证措辞统一+补文件名）新增字符使 ch-A 达 704 字、超出规格单上限 700——verify_draft 当场拦截。处理：主 Agent 最小修剪响应段冗余（-5 字）→ PASS。**启示**：规格单字数区间应给审计修复预留 ~5% 余量，否则审计修复会系统性撞线（W3 3.2 规格单 schema 增补建议）。
2. **writer 双双诚实上报限制**：规格单缺"权重/格式要求/禁止项"独立字段（按 SKILL 默认工艺兜底并报告）；无 shell 无法算 sha256（fingerprint 如实标 unavailable/null）。**规格单 schema v2 应补齐三字段 + 主 Agent 落盘规格单后派路径**（writer 无法对内嵌文本算指纹）。
3. **素材指针双根歧义**：`kb/raw/...` 相对根在数据面（~/.bidmaster）不存在，实际在仓库——两位 writer 都自行解析到仓库路径并如实注明。规格单指针应写全路径或定义统一根（修订项）。
4. **auditor 质量亮点**：阴性对照主动报告（防回归基线）；存疑不凑数（3 项存疑沿用不翻新，其中 W1 正确归因为规格单缺口而非 writer 缺陷）；round-2 严守收敛纪律（只核 5 项、逐项带当前版本逐字证据）。
5. ch-B 主动执行 L3 自检：素材中的证书编号、个人姓名、热线均未落入产物。
